Кадр - frontend

Вебінтерфейс AI Video Generation Pipeline команди SpaceY. React 19, TypeScript, Vite, Lucide. Вихідний код розділений на компоненти, типи, стилі та ресурси.

Запуск

Потрібні Node.js 22.12 або новіший та npm.

npm ci
npm run dev

Адреса застосунку з’явиться в терміналі. Vite за замовчуванням використовує http://127.0.0.1:5173. Відкрити саме цю адресу в браузері та залишити термінал запущеним. Якщо порт зайнятий, використати адресу з іншим портом, яку показує Vite.

index.html не запускається подвійним кліком. Він підключає src/main.tsx, який Vite перетворює з TypeScript/TSX на JavaScript для браузера. Відкриття через file:// обходить цей процес і може показати порожню сторінку.

npm ci встановлює залежності після розпакування проєкту або оновлення package-lock.json. Для наступних запусків достатньо npm run dev. Папка node_modules створюється автоматично та не потрібна в архіві для передачі.

npm run build
npm run preview

Команда build перевіряє TypeScript і створює статичну збірку в dist. preview запускає перегляд цієї збірки. Файл index.html є точкою входу Vite; для розробки застосунок запускається через npm.

Структура

src/main.tsx - Запуск React і підключення стилів
src/App.tsx - Навігація, стан чернетки, проєкти, імпорт, експорт і завантаження матеріалів
src/Studio.tsx - Чотири кроки редактора та їхня валідація
src/Pages.tsx - Медіатека й налаштування
src/types.ts - Типи Draft, Project, MediaItem, Settings та значення форматів
src/storage.ts - localStorage, завантаження файлів та формування SRT
src/data.ts - Початкові матеріали, приклади проєктів і локальні шаблони сценарію
src/ui-kit/index.tsx - Спільні компоненти, картки, діалоги та попередній перегляд
src/ui-kit/styles.css - Основні й адаптивні стилі
src/ui-kit/tokens.css - Кольори, відступи та інші токени
src/ui-kit/fonts.css - Підключення локальних шрифтів
public/assets - Фотографії та ліцензія шрифту
vite.config.ts - Конфігурація Vite та проксі для API під час розробки

Поточна поведінка

Інтерфейс працює локально. Проєкти й налаштування зберігаються в localStorage. Власні медіафайли доступні до перезавантаження сторінки через тимчасові blob-адреси. Локальні шаблони сценарію та зразок голосу в браузері не звертаються до сервера. Попередній перегляд показує вибрані матеріали; завершення зберігає конфігурацію та відкриває експорт JSON/SRT.

Підключення backend

Збереження й отримання проєктів - App.tsx: стан projects, функції saveProject, openProject, projectAction; поточне сховище реалізоване у storage.ts
Генерація сценарію - Studio.tsx: generateScript і створення початкового тексту в nextStep; зараз вони викликають createScriptTemplate з data.ts
Озвучення - Studio.tsx: previewVoice; замінити браузерний зразок отриманням аудіо від сервера
Добір матеріалів - Початкова колекція mediaLibrary у data.ts; пошук на екранах фільтрує цю колекцію локально
Завантаження файлів - App.tsx: uploadFiles, removeUpload; замість blob-адрес зберігати ID й URL від сервера
Монтаж та експорт MP4 - App.tsx: обробник onGenerate, переданий у Studio; тут запускати серверне завдання та відображати його стан і посилання на результат
Передача параметрів - App.tsx: exportProject уже збирає конфігурацію з темою, текстом, голосом, матеріалами, музикою та параметрами вихідного відео

Адреси маршрутів, формат відповідей, авторизацію та стани серверного завдання потрібно узгодити з backend. Типи у src/types.ts описують поточний інтерфейс і можуть бути адаптовані до узгодженого API. Запити до API та серверна генерація MP4 ще не реалізовані.

Проксі під час розробки

У конфігурації є проксі з /api на http://127.0.0.1:8000. Він зберігає шлях запиту: /api/projects буде передано як /api/projects. Це приклад адреси для налаштування проксі, а не вже реалізований маршрут.

Якщо сервер працює за іншою адресою, скопіювати .env.example у .env.local та змінити API_PROXY_TARGET. Після зміни перезапустити Vite. Після підключення API фронтенд може використовувати відносні адреси /api/....

Проксі Vite працює лише з npm run dev. Для опублікованої збірки потрібно налаштувати передачу /api на backend у вебсервері або адаптувати клієнт до окремої адреси API. Ключі сервісів зберігаються на backend і не включаються у frontend.
